# 压缩、检查点与轨迹

## 压缩目标

长会话在切换模型、恢复和上下文超限时保持消息一致性。压缩由 K-brain 后端执行，LiveAgent 显示状态和结果。历史原文、活动上下文、文件记录和压缩摘要分别管理。

实现入口包括 `internal/agent/agent.go`、`internal/agent/compact_transaction.go` 和 `internal/backend/compact.go`。

## 触发与事务

需要逐项验证：用户手动触发、达到上下文阈值、请求发送前适配目标上下文、供应商报告溢出后的恢复，以及工具阶段/流式阶段的边界。

一次轮次中的压缩应遵循明确的重复执行规则。摘要生成失败、超时、取消或历史 revision 冲突时保留原活动上下文。手动压缩使用后端运行身份和持久化记录，关闭服务等待其终态落盘。

当前手动、阈值和请求适配路径已有实现与回归；独立 post-tool、mid-stream 行为及各协议组合继续按兼容矩阵验证。

## 文件记录与检查点

工具修改文件时记录对应消息/运行、修改前内容、缺失状态及恢复所需元数据。回退先 preview，再根据 revision 执行 rewind；发生变化时返回冲突。

旧数据迁移保留源历史与检查点关系，支持二进制前像。部分导出、缺失原始记录、大文件和目录恢复应显示具体限制。文件路径验证与并发 rename/symlink 之间的时间差仍需专门处理。

## 轨迹

轨迹记录模型请求、工具、审批、子代理和用量，支持按窗口查看及统计。后端持久记录是调试依据，前端呈现可以增量加载。

无后端会话的本地草稿返回空轨迹；已有会话读取失败应显示错误并可重试。前台子代理、后台子代理和 Gateway 三条路径分别验证。

## 验证

- 压缩前后历史与活动上下文对照；失败回滚和幂等重试。
- CLI、ACP、桌面与 Gateway 的恢复行为。
- 真正的工具改文件 → checkpoint → preview → rewind → 重启读取。
- 真实 Agent/工具/子代理事件进入 HTTP 与 UI 轨迹。
- 用当前后端执行产生的证据记录结论，参考项目的历史截图和测试记录只用于理解设计。
