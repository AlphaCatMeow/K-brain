# 界面与交互

## 保留的界面

LiveAgent 的原布局、供应商设置、模型选择、历史、工作空间、工具与资源入口继续使用。桌面和 Web 共享组件位于 `LiveAgent/crates/agent-ui/`，宿主适配分别位于 `agent-gui` 和 `agent-gateway/web`。

## 异步状态

操作状态包含所属会话、请求标识和适用版本。网络响应、动画帧、组件卸载和会话切换可能打乱返回顺序，应在写入状态前核对归属。

重点场景：

- 队列编辑从开始到保存/取消持续绑定原 conversation/item。
- 草稿切换保留用户输入、附件和焦点，避免异步回调覆盖新草稿。
- 历史加载失败不清空已有有效消息；重试与新会话创建相互独立。
- Cron 任务切换、日志清空和重载忽略过期响应。
- 设置保存成功后更新目录；模型切换不丢失当前会话上下文。

## 流式呈现

文本、思考、工具、审批和子代理均保留事件身份。客户端按序号去重，终态消息与增量合并后保持单次呈现。长消息、代码块、图片和错误消息需在桌面与移动端检验宽度与滚动。

自动跟随仅在用户仍处于跟随状态时发生。用户向上阅读、选择文本或打开菜单时保留视图位置。错误内容需要可见、可定位，并在历史重载后保留。

## 移动端

使用 `390×844` 检查导航、composer、队列操作、审批、模型选择和资源设置。测试触控可达性、软键盘空间、横向溢出、弹窗关闭与返回路径。移动端编辑必须完成保存/取消的实际 RPC 闭环。

## 验收规则

每次共享组件变更都检查所有使用该组件或状态的页面。Gateway 状态页的 `/dashboard`、`/status-board`、`/observatory` 是同一功能的路由别名，出现的功能阻塞应统一记录。

真实浏览器操作与单元测试互补。页面能渲染只证明渲染成功；请求、结果、持久化与重载都完成后，才能认定流程通过。
