# 后端会话队列

K-brain 接收并持久化完整的 canonical 请求，串行派发；Gateway 与客户端只提交、
订阅与修改队列，不自行判断后端空闲。现有 `/runs` 立即执行接口保留，队列有待执行项时
拒绝插队。新增 `/queue` GET/POST 与 `/queue/actions` POST，通过 health 的
`session_queue: 1` 选择协议，旧后端保留既有兼容路径。

提交以 client_request_id 去重，同身份不同原始载荷返回冲突；编辑通过单独的 revision
校验操作完成，删除项保留去重收据，旧请求重试不会复活已删除项。队列最多 128 项，
每会话最多 4096 个收据，文档最多 16 MiB；达到上限明确拒绝，不静默丢弃身份。
持久化采用临时文件、同步与原子替换。入队成功不代表模型已经执行。

队列快照沿用 conversationId/revision/items，每项带 clientRequestId；详情提供完整
request、draftJson、uploadedFilesJson。修改使用当前 revision（包括编辑开始、排序、
删除、暂停、恢复）；冲突返回当前快照。编辑保存保留原身份及位置。

队列工作协程只在存在未暂停工作时持有会话租约，通过既有事件唤醒，不用轮询；
等待前一轮真实结束后派发。取消等待项和取消正在运行的任务分开处理。
interrupt/run_now 先持久化排序，再取消当前轮，取消失败不得并行派发。

进程重启后惰性加载持久化队列，默认暂停，由显式 resume 恢复；已经有 canonical
运行收据的项只关联原运行，绝不重新执行。关闭后端取消队列协程，保留待执行项。
此批先接通后端与 Gateway；桌面本地队列迁移另行完成，不能声称所有入口已统一。

验收覆盖真实 HTTP、重复/冲突提交、revision 冲突、FIFO、编辑/取消编辑、删除、
中断、失败、重启、持久化故障、并发与关闭。浏览器验证单独记录，不能把协议测试当作
完整 WebUI 或原生桌面验收。

## 下一批与已知边界

- 桌面本地执行入口仍保留旧队列，尚未统一迁到本接口。
- 后端支持 canonical content 附件；Gateway 当前 PromptRequest 仍是文本入口，上传附件解析未迁移，不计入本批完成项。
- 后端恢复队列默认暂停；WebUI 尚无暂停/恢复专用按钮，需显式调用 actions/resume，或选择某项“打断并执行”。
- Gateway 接入旧后端或仍有旧队列时保留旧执行路径；旧队列排空后的能力切换目前通过重启 Gateway 完成。
- 队列读取目前需要可加载的会话运行时；无凭据、已删除模型下的纯只读队列访问尚未独立。
- 每会话 4096 个收据达到上限后拒绝继续入队；没有自动清理收据以免破坏去重，需要后续设计归档协议。
- Gateway 的事件游标恢复不能宣称跨进程崩溃的 UI exactly-once；后端接受身份防止重复执行，前端事件去重仍依赖现有序号处理。
