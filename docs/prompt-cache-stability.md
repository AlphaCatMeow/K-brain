# 模型输入缓存：稳定前缀与验收（2026-10-07）

## 对照参考项目

- `deepseek-harness/packages/core/agent-loop/tests/request-cache.e2e.ts` 保持系统提示和历史消息前缀不变，新工具结果和用户问题只追加到末尾；真实 API 测试断言后续请求有缓存读取，不承诺 97%。其部分日志中的 `inputTokens` 是未缓存输入，比例应为 `cacheReadTokens / (inputTokens + cacheReadTokens)`。
- `zcode/apps/zcode-cli/packages/core/src/context/builder.ts` 把稳定系统内容放前面、动态内容放后面，为 Anthropic 内容块设置缓存边界。`packages/bootstrap/src/zcode-protocol/usage-stats-builder.ts` 的输入已经包含缓存，不能再加一次缓存读取量。
- KB 的 `PromptTokens`、协议的 `input_tokens` 均为总输入，`cached_tokens` 是其子集。LA 轨迹使用未缓存输入、缓存读取、缓存写入分项，现有累计命中率计算正确，本次没有更改统计口径。

## 实现

1. 后端每轮解析规则时改用 `prompts.BuildStable`。移除默认环境块每秒变化的当前时间，保留项目 AGENTS、brain、系统模板、技能和记忆的正常刷新。
2. 后端启用 `agent.WithTurnTimeContext`，向模型请求中的用户消息添加持久化发送时间。使用 UTC RFC3339，重载或本机时区改变不会重新生成旧消息的时间。时间不写进聊天正文，不影响图片附件；没有时间的旧消息不猜测时间。
3. `ContinueUser` 复用已持久化的完整用户消息，使记录器与模型请求看到相同的时间和内容。
4. 工具定义按名称稳定排序，避免 MCP 发现顺序变化导致 schema 顺序改变；不改变执行工具列表。
5. Anthropic 在最终工具定义（包括原生搜索）添加缓存边界，加上既有系统和消息边界共三个，低于四个上限。关闭缓存时不发任何边界。不新增不受支持的 TTL 参数。

时间处理是显式 agent 选项，后端默认启用；既有 CLI/ACP 的单次构造提示及第三方直接使用 Agent 的消息正文保持兼容。工具顺序和 Anthropic 边界适用于共享这些组件的调用路径。

## 边界

97% 不是客户端可以保证的固定数值。冷请求、工具集合变化、真实规则/记忆更新、压缩历史、供应商缓存分块、过期和路由都可能降低命中。本轮新增 MCP 后请求为零命中，之后缓存恢复；没有供应商内部日志，不能据此断言唯一原因。

本次消除了可确定的无意义前缀变化，没有缓存工具执行结果，没有关闭记忆刷新或历史压缩，也没有靠填充无用文本提高百分比。用户自定义提示中自行生成的动态内容不被重写。单次 98% 不代表所有会话或整段会话稳定达到 97%。
